# 视觉合成（任务B）的输入素材：手上到底有什么

**这份文档只陈述量出来的事实**，不含实现方案 —— 目的是让"抠掉人、贴上机器人"这件事
开工之前，先把"每一样输入从哪来、哪一样根本不存在"钉死。写法照 [`LEROBOT_ALIGNMENT_GAP.md`](LEROBOT_ALIGNMENT_GAP.md)
（任务A）：先量，再谈怎么做。

目标形态（2026-08-21 会议定的②，走**低成本路线**，不要 ProPainter 级依赖）：
遮罩掉画面里的人手/手臂 → 补背景 → 把渲染的机器人按深度合进去。
参考 Phantom（arXiv 2503.00779）和 Ego2Robot（arXiv 2608.02580）。

## 1. 逐样输入：从哪来 / 有没有

| 输入 | 状态 | 从哪来 | 备注 |
|---|---|---|---|
| **原始 RGB 画面** | ❌ **卡住** | 官方片段里一帧都没有；只能从 YouTube 原片还原 | 下载被 PO Token 拦，见 BACKLOG **B12**（待拍板）。截取+对齐那一半已完工（`src/web2robot/fetch/`） |
| **场景深度（毫米）** | ✅ 已补齐 | HF 的 `depth.npz`（uint16 毫米，(T,480,853)） | 本地原有的 `depth.mp4` 是 **8 位归一化、没存标定尺度**，没法和机器人渲出来的米制深度比大小 → 深度排序必须用 npz。补齐脚本 `scripts/dev/fetch_official_extras.py` |
| **手部掩码** | ✅ 已实现 | HF 的 `hand_verts.bin` + `hand_faces.bin`（MANO 网格）+ `camera.json` 内参 → **逐帧对齐** → 光栅化 | 零新依赖。但**不是投影一下就对**，见 §2 第 5 条和 §3.5；代码 `src/web2robot/synth/`，跑法 `scripts/s5_hand_mask.sh` |
| **人体/手臂掩码** | ⚠️ 官方**没有** | 得自己出 —— 见 §3 | 会议记录里写的是 SAM3，但磁盘上没有 SAM3 权重 |
| **物体掩码** | ✅ 有 | `masks.npz`（逐物体、按位打包） | 解码口径 `scene.json` 自己写了：`np.unpackbits(arr[oid_K][t])[:H*W].reshape(H,W)` |
| **物体三维外观** | ✅ 有 | `objects/obj_0.ply` —— **是 3D Gaussian Splat**（有 `f_dc_*` / `opacity` / `scale_*` / `rot_*`） | 物体位姿 `object_pose.bin` (T,1,4,4) + OBB。要重渲物体时白拿 |
| **机器人渲染 + 机器人深度** | ✅ 我们自己出 | MuJoCo（M7 资产 + 重定向出的关节角） | 现有 `robot_sim.mp4` 那条渲染链就是它 |
| **接触/抓握逐帧信号** | ✅ 有 | `signals.json`（`contact_l`/`contact_r`/`grasp`/`motion`） | 合成时判"这一帧该不该有手/该不该贴夹爪" |
| **相机内参** | ✅ 有 | `camera.json`：focal 966.56、cx 426.5、cy 240.0、853×480，另带 `gravity_up` | 单相机、无畸变参数 |

补齐的那几件放在片段目录里（和 `scene.json` 里写的相对文件名一致），清单
`data/clips_official/EXTRAS.md5`。**已 grep 确认 `external/EgoInfinity/` 全仓库没有
一处引用这几个文件名**，所以补进去不改变现有重定向行为 —— 这不是推测。

## 2. 五个已经踩到的坑（都验过）

1. **`mask.mp4` 不是人的掩码，是物体掩码。** 非零面积只占 3–10%，而且是**软掩码**
   （200+ 个灰度值，不是 0/255）。想当"人的轮廓"用会直接错。
2. **`mask.mp4` 宽 854，`camera.json` 说 853。** h264 的偶数宽度对齐。任何"掩码和画面
   逐像素对应"的代码必须显式处理这 1 像素，别指望默认行为。
3. **`pose_track.json` 是物体的跟踪轨迹，不是人体姿态**（顶层键就是物体 id `"0"`，
   里面是 `mode: position_first` / `anchor_t` / `scale_correction` 这类字段）。
   官方数据里**没有人体骨架**。
4. **`thumb.jpg` 和 `bg_template.png` 都是深度，不是画面。** `thumb.jpg` 是深度图的
   伪彩缩略图，`bg_template.png` 是 853×480 的 **uint16 深度**背景板。别拿它们当 RGB
   兜底（我一开始差点这么干）。
5. **官方 3D 手直接投影，对不上画面。** 这是本文档最要紧的一条更正（早先我写的是
   "几何精确"）。拿 `camera.json` 把 `hand_joints.bin` 投到像素平面，和官方
   `hand_joints_2d.bin` 比：**差 9.3 px 中位**（最差一段 71 px）。全段统一拟合一个
   缩放+平移也只降到 4.4–19.5 px；**逐帧逐手**拟合才降到 3.7 px，而解出来的缩放
   逐帧在 **0.32–0.95** 之间漂（`-0RheyDV3a0_474.8_487.3` 中位 0.67，全 10 段合起来
   0.088–1.806）。也就是说官方 3D 手的**尺度/深度是逐帧不定的**（单目手部深度的老
   问题），像素空间里的真值是那份 2D 关节。所以流程必须是
   「投影 → 逐帧逐手相似变换 → 光栅化」。少这一步，贴上去的机器人手会整体错位。
   顺带一条：把模型从"缩放+平移"放宽到**全仿射**，残差只从 8.96 降到 8.52 px（最差
   那段）—— 说明剩下的误差是官方数据里 3D 和 2D 的手势本身不一致，不是我的 2D 模型
   自由度不够。**所以不加复杂度**。

## 3. 人体/手臂掩码怎么来：现状与我的取法

会议记录写的是 SAM3。**磁盘上没有 SAM3 权重**（`assets/weights/` 只有一个
`keypointrcnn` 的 symlink），`configs/paths.yaml` 里也没有登记任何分割模型。

我的取法（**不引入任何 pip 安装**，也不锁死在某个模型上）：

- **默认**：torchvision 的 Mask R-CNN（COCO `person` 类）出人体实例掩码，
  与 MANO 手部掩码求并集，再做可控膨胀。理由是这条路**与仓库现有做法同构** ——
  质检模块 `quality/pose_gate.py` 已经在用同样的方式（`TORCH_HOME` 指到
  `assets/weights/`，torchvision 自动下权重），不是新的依赖类别，只是多一份权重文件。
- **接口留成可插拔**：掩码从一个目录读（`--mask_dir`），谁产的都行。以后真要上 SAM3
  或公司内部的分割服务，把掩码丢进那个目录即可，合成代码不用改。

这是"有惯例默认值"的选择，所以我按惯例定了，没拿它去占用拍板队列；
真正需要你拍板的只有 B12（RGB 字节从哪来）。

### 3.5 手部掩码：已做完的部分和它的判据

`src/web2robot/synth/`，`scripts/s5_hand_mask.sh data/clips_official --out outputs/synth`。
10 段官方片段全跑通，产物是 `handmask_check.png`（核对图）+ `hand_masks.npz`（按位打包）
+ `handmask.jsonl`（逐段判据）。

判据是官方 `hand_joints_2d.bin` 的 21 个关节点落在掩码里的比例，**分指尖和非指尖两组
报**：指尖骨节点在网格表面上或略微在外（实测落在外面的离掩码边界中位只有 2 px，其余
关节 1 px），混在一起算会把"几何本来如此"和"掩码错位"搅成一个数。10 段合并：

| | 非指尖 | 指尖 |
|---|---|---|
| 逐帧对齐（默认） | **0.964** | 0.789 |
| 不对齐（`--no_align` 对照） | 0.765 | 0.457 |

最差的一段是 `-20k07PjLTA_48.0_52.4`（非指尖 0.847，拟合残差 7.04 px）—— 那段的官方
3D 手势和 2D 本身就不一致，不是掩码的问题（记进 BACKLOG **B13**）。

**这条判据只有一半独立性**：对齐用的就是这份 2D 关节，所以它证的是"网格形状 + 那个
变换能把关节包住"，证不了 3D→2D。真正独立的复验是核对图 —— 但底图现在是**深度**
（`depth.npz`），因为真 RGB 还卡在 B12。手在深度图里轮廓清楚，掩码贴不贴边一眼能看
出来，我逐段看过。RGB 到位之后把底图换掉即可，其余不动。

## 3.6 按片段那台相机把机器人渲出来（第二块，已做完）

`src/web2robot/synth/render.py` + `scripts/s6_robot_render.sh`。合成要把渲好的机器人
**贴回原画面**，所以渲出来的这一台必须和画面共用同一台相机 —— 内参、外参、逐帧位姿
三样都得对上，差一样就是"贴上去但对不齐"。

```bash
scripts/s6_robot_render.sh data/clips_official \
    --runs_dir outputs/retarget/collcmp --pattern '*_grid' --out outputs/synth/render --npz
```

产物逐段三样：`robot_render_check.png`（九宫格核对图）、`robot_render.mp4`（h264）、
`robot_render.npz`（`depth_mm` uint16 + 按位打包的 `mask`，给合成用）。

**为什么不能用上游那份渲染**：上游 `test.py::render_robot_sim` 用的是自由视角相机、
只出彩色、分辨率写死 1080×1440。它是给人看轨迹对不对的，不是给合成用的。

**三件要对上的事，各自怎么解**：

| 要对上什么 | 怎么解 |
|---|---|
| 内参 | `fovy = 2·atan(H/2f)`，往内存里那份模型 `add_camera` 加一台。**前提是主点居中** —— 10 段官方片段实测 `cx == W/2`、`cy == H/2` 逐位精确成立，所以不用改投影矩阵；不成立的片段直接 `CameraNotSupported` 报错，不做近似 |
| 外参 | `root_frames.npz` 的 `R_per_frame`/`t_per_frame` 是**根 link（`waist_pitch_link`）在片段相机系里**的位姿（依据：上游 `test.py:518` 拿它当 `draw_frame` 的 `root` 画在画面上）。反解相机在 MuJoCo 世界系里的位姿，再乘 `diag(1,-1,-1)` 换 OpenCV→MuJoCo 的轴向 |
| 逐帧位姿 | `trajectory.npz` 的双臂 + 双手关节角，逐帧 `mj_forward` |

**踩到的两个坑（都写进了模块 docstring）**：

1. **场景 XML 不能用 `scene_vis.xml`** —— 它带一块无限大地板，从片段相机的视角看过去
   直接糊满整幅画面。要用 robot-only 的 `m7.xml`。
2. **写完 `model.cam_pos` 必须自己补一次 `mj_camlight`** —— `mjv_updateScene` 读的是
   `data.cam_xpos`，而写 `model` 不会更新 `data`。不补的后果是**静默的**：第 0 帧从世界
   原点拍（66% 的像素落在 2.6–4.4 cm），之后每一帧都用上一帧的相机。静态根位姿的 grid
   片段上肉眼看不出来，neural 片段上全程错。`tests/test_synth_render.py` 里有一个
   顺序无关性回归测试钉住这条，删掉 `mj_camlight` 会红 3 个。

**判据：把"错位"拆成两段，各自报中位**（因为 B13 已经证明官方 3D 手和官方 2D 关节
自己就对不上，混在一起报会把别人的账记到我们头上）：

- `robot_mano_px` = 机器人手腕投影 ↔ 官方 3D 手腕投影 —— **这一段才是我方链路的账**
- `mano_2d_px` = 官方 3D 手腕投影 ↔ 官方 `hand_joints_2d.bin` —— 官方数据自相矛盾（B13）
- `robot_2d_px` = 两者叠加，也就是画面上实际看到的错位

8 段 × 2 只手实测（`outputs/synth/render/render.jsonl`）：`robot_mano_px` 中位
**1.72 px**，16 只手里 11 只 < 2 px。剩下 5 只的成因**逐只归因过**，见
`docs/VERIFICATION.md` ⑦ 那节的表 —— 两只是 IK 没解出来（源头坏帧），两只是碰撞过滤
把手推走了（BACKLOG **B15**），一只是 IK 有个别尖峰帧。

**还是只有一半独立性**：这一段量的是"手腕落点"，不是"整台机器人贴得对不对"。真正的
复验要等真 RGB（B12）—— 现在核对图的底图还是深度。

### 3.7 抠人 → 补背景 → 按深度贴机器人（第三块，已做完）

`src/web2robot/synth/compose.py` + `scripts/s7_compose.sh`。把前两块的零件拼成一帧最终
画面，8 段官方片段全跑通，产物是 `compose_check.png`（三列并排：原画面 / 抠人补背景 /
合成）+ `compose.mp4`（h264）+ `compose.jsonl`（逐段判据）。数字和核对图在
[`VERIFICATION.md`](VERIFICATION.md) ⑧。

深度排序那条规则里有两处**看着像放水、其实必须有**的例外：

| 例外 | 为什么必须有 |
|---|---|
| 被抠掉的人形区域内**无条件**画机器人 | 那块地方 `depth.npz` 存的是**人手自己的深度**（人还在画面里时测的）。人已经擦掉了，拿这个深度去挡机器人，等于让一个不存在的东西遮住机器人 —— 而机器人本来就是来接替那只手的 |
| 场景深度无效（0）的像素不参与判遮挡 | 官方那些像素本来就没测出来（反光/太远/重建失败）。深度未知就不能判遮挡，否则整片黑洞会把机器人啃掉 |

例外有代价（掩码溢到桌沿上，机器人会盖住桌沿），所以**量了**：`robot_override_fraction`
8 段 0.009–0.049，也就是机器人像素里约 2% 靠这条例外画出来，现在可忽略；换成整人分割之后
这个数会长，要重量（记进 BACKLOG **C26**）。

**机器人是现渲，不读 `robot_render.npz`** —— 那份 npz 只有深度和掩码、**没有彩色**
（存彩色是 190 MB 量级，而且换一次重定向就成了过期数据）。所以走 `ClipRobotRenderer`
和 `render` 子命令**同一条代码路径**，彩色/深度/掩码天然自洽。

## 4. 补背景（inpaint）怎么做（已实现，见 §3.7）

低成本路线，两条都不需要新依赖：

- **相机固定的片段**：用整段的**时间中值**做背景板（掩码外的像素参与统计）。
  中值不是均值 —— 手扫过某个像素的帧数只要少于一半，中值完全不受影响，均值会留一道淡影
  （`tests/test_synth_compose.py` 里两条并排钉住）。整段都被挡住的像素中值给不出值，
  用 `cv2.inpaint` 补，不留黑洞。
- **相机运动的片段**：`cv2.inpaint`（Telea），逐帧。cv2 5.0.0 现成。
- **走哪条**：`--plate median|inpaint` 显式指定，或者 `auto` 按相邻帧差猜。
  相机动不动这件事第②步路由已经在判了，**有那个标签时就该用它，别靠猜** ——
  那个阈值在替身底图上标不了（深度图比 RGB 平滑，8 段的分全在阈值以下），见 BACKLOG **C25**。

真验还是要等 RGB 到位（B12 的下游）：现在底图是深度替身，而且 `depth_background()` 是
**逐帧各自拉伸**的，同一个背景像素在不同帧的灰度值本来就不完全一样 —— 替身上的背景板
好不好看，说明不了真画面上好不好看。

## 5. 结论：现在能推进什么、什么必须等

| | 依赖 B12 吗 | 现在能做 |
|---|---|---|
| 手部掩码光栅化（MANO → 掩码） | 不依赖 | ✅ **已做完**，见 §3.5 |
| 按片段相机渲机器人（彩色+深度+掩码） | 不依赖 | ✅ **已做完**，见 §3.6 |
| 深度排序合成的核心逻辑 | 不依赖 | ✅ **已做完**，见 §3.7；真画面到位再复验 |
| 补背景（两条路的实现） | 不依赖 | ✅ **已做完**，见 §4；**好不好看要等真画面才算数** |
| 人体掩码（Mask R-CNN） | **依赖** | ❌ 没有 RGB 就没有输入。所以现在"抠人"实际只抠了**手**（0.011–0.034 的画面面积），人还留在画面里 |
| 端到端"抠人换机器人"出片 | **依赖** | ⚠️ **链路已经跑通并出片**（8/8 段），但两处是占位：底图是深度替身、抠掉的只有手。这两处都只等 B12，不等别的 |
