# 视觉合成（任务B）的输入素材：手上到底有什么

**这份文档只陈述量出来的事实**，不含实现方案 —— 目的是让"抠掉人、贴上机器人"这件事
开工之前，先把"每一样输入从哪来、哪一样根本不存在"钉死。写法照 [`LEROBOT_ALIGNMENT_GAP.md`](LEROBOT_ALIGNMENT_GAP.md)
（任务A）：先量，再谈怎么做。

目标形态（2026-08-21 会议定的②，走**低成本路线**，不要 ProPainter 级依赖）：
遮罩掉画面里的人手/手臂 → 补背景 → 把渲染的机器人按深度合进去。
参考 Phantom（arXiv 2503.00779）和 Ego2Robot（arXiv 2608.02580）。

## 2. 五个已经踩到的坑（都验过）

1. **`mask.mp4` 不是人的掩码，是物体掩码。** 非零面积只占 3–10%，而且是**软掩码**
   （200+ 个灰度值，不是 0/255）。想当"人的轮廓"用会直接错。
2. **`mask.mp4` 宽 854，`camera.json` 说 853。** h264 的偶数宽度对齐。任何"掩码和画面
   逐像素对应"的代码必须显式处理这 1 像素，别指望默认行为。
3. **`pose_track.json` 是物体的跟踪轨迹，不是人体姿态**（顶层键就是物体 id `"0"`，
   里面是 `mode: position_first` / `anchor_t` / `scale_correction` 这类字段）。
   官方数据里**没有人体骨架**。
4. **`thumb.jpg` 和 `bg_template.png` 都是深度，不是画面。** `thumb.jpg` 是深度图的
   伪彩缩略图，`bg_template.png` 是 853×480 的 **uint16 深度**背景板。别拿它们当 RGB
   兜底（我一开始差点这么干）。
5. **官方 3D 手直接投影，对不上画面。** 这是本文档最要紧的一条更正（早先我写的是
   "几何精确"）。拿 `camera.json` 把 `hand_joints.bin` 投到像素平面，和官方
   `hand_joints_2d.bin` 比：**差 9.3 px 中位**（最差一段 71 px）。全段统一拟合一个
   缩放+平移也只降到 4.4–19.5 px；**逐帧逐手**拟合才降到 3.7 px，而解出来的缩放
   逐帧在 **0.32–0.95** 之间漂（`-0RheyDV3a0_474.8_487.3` 中位 0.67，全 10 段合起来
   0.088–1.806）。也就是说官方 3D 手的**尺度/深度是逐帧不定的**（单目手部深度的老
   问题），像素空间里的真值是那份 2D 关节。所以流程必须是
   「投影 → 逐帧逐手相似变换 → 光栅化」。少这一步，贴上去的机器人手会整体错位。
   顺带一条：把模型从"缩放+平移"放宽到**全仿射**，残差只从 8.96 降到 8.52 px（最差
   那段）—— 说明剩下的误差是官方数据里 3D 和 2D 的手势本身不一致，不是我的 2D 模型
   自由度不够。**所以不加复杂度**。

## 3. 人体/手臂掩码怎么来：现状与我的取法

会议记录写的是 SAM3。**磁盘上没有 SAM3 权重**（`assets/weights/` 只有一个
`keypointrcnn` 的 symlink），`configs/paths.yaml` 里也没有登记任何分割模型。

我的取法（**不引入任何 pip 安装**，也不锁死在某个模型上）：

- **默认**：torchvision 的 Mask R-CNN（COCO `person` 类）出人体实例掩码，
  与 MANO 手部掩码求并集，再做可控膨胀。理由是这条路**与仓库现有做法同构** ——
  质检模块 `quality/pose_gate.py` 已经在用同样的方式（`TORCH_HOME` 指到
  `assets/weights/`，torchvision 自动下权重），不是新的依赖类别，只是多一份权重文件。
- **接口留成可插拔**：掩码从一个目录读（`--mask_dir`），谁产的都行。以后真要上 SAM3
  或公司内部的分割服务，把掩码丢进那个目录即可，合成代码不用改。

这是"有惯例默认值"的选择，所以我按惯例定了，没拿它去占用拍板队列；
真正需要你拍板的只有 B12（RGB 字节从哪来）。

### 3.5 手部掩码：已做完的部分和它的判据

`src/web2robot/synth/`，`scripts/s5_hand_mask.sh data/clips_official --out outputs/synth`。
10 段官方片段全跑通，产物是 `handmask_check.png`（核对图）+ `hand_masks.npz`（按位打包）
+ `handmask.jsonl`（逐段判据）。

判据是官方 `hand_joints_2d.bin` 的 21 个关节点落在掩码里的比例，**分指尖和非指尖两组
报**：指尖骨节点在网格表面上或略微在外（实测落在外面的离掩码边界中位只有 2 px，其余
关节 1 px），混在一起算会把"几何本来如此"和"掩码错位"搅成一个数。10 段合并：

| | 非指尖 | 指尖 |
|---|---|---|
| 逐帧对齐（默认） | **0.964** | 0.789 |
| 不对齐（`--no_align` 对照） | 0.765 | 0.457 |

最差的一段是 `-20k07PjLTA_48.0_52.4`（非指尖 0.847，拟合残差 7.04 px）—— 那段的官方
3D 手势和 2D 本身就不一致，不是掩码的问题（记进 BACKLOG **B13**）。

**这条判据只有一半独立性**：对齐用的就是这份 2D 关节，所以它证的是"网格形状 + 那个
变换能把关节包住"，证不了 3D→2D。真正独立的复验是核对图 —— 但底图现在是**深度**
（`depth.npz`），因为真 RGB 还卡在 B12。手在深度图里轮廓清楚，掩码贴不贴边一眼能看
出来，我逐段看过。RGB 到位之后把底图换掉即可，其余不动。

## 4. 补背景（inpaint）怎么做

低成本路线，两条都不需要新依赖：

- **相机固定的片段**：用整段的**时间中值**做背景板（掩码外的像素参与统计）。
  相机动不动这件事第②步路由已经在判了，直接用它的标签。
- **相机运动的片段**：`cv2.inpaint`（Telea / Navier-Stokes），逐帧。cv2 5.0.0 现成。

两条都在 RGB 到位之后才能真验 —— 这是 B12 的下游。
